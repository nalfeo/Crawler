# 2026-06-08 — Pixels to Feet Migration

## Summary

Migrated all authored spatial measurements from pixels to feet. ECS stores and physics math remain in pixels. Players will now see intuitive values like "Range: 45'" or "Sniper Rifle: 100'".

## What Changed

### New file: `src/shared/units.ts`

- `PIXELS_PER_FOOT = 8`
- `ftToPx(feet)` — convert authored feet to pixels at design→ECS boundary
- `pxToFt(pixels)` — convert pixels to feet for UI display
- `formatFeet(pixels)` — format as "5'" string

### Design authoring layer (now in feet)

- `src/shared/data/tuning.json` — all distance fields
- `src/shared/weaponDefs.ts` — all distance fields (literals only; WEAPON.\* constants not used for distances to avoid double-conversion)
- `src/game/skills/registry.ts` — Juggernaut aura radius (48px → 6ft)
- `src/shared/data/weapons.json` — updated for consistency (not imported at runtime)

### Conversion boundary (weaponSystem.ts)

All 5 attack type dispatchers now call `ftToPx()` when passing def distances to spawners:

- `fireMeleeAttack`: aoeRadius, headRadius, knockback
- `fireMagicAttack`: aoeRadius
- `fireThrownAttack`: maxRange
- `fireBeamAttack`: beamLength
- `fireTrapAttack`: trapTriggerRadius, trapExplosionRadius

### System constants (now ftToPx-authored)

- `constants.ts`: WEAPON.\* distances and ENEMY_PROJECTILE.MUZZLE_OFFSET
- `enemyAISystem.ts`: SWARM_NEIGHBOR_RADIUS = ftToPx(4) [was 30, now 32]
- `enemySpawnerSystem.ts`: ENEMY_RADIUS = ftToPx(1) [still 8]
- `returningProjectileSystem.ts`: PICKUP_RADIUS_SQ = ftToPx(2)\*\*2 [still 256]
- `dropSystem.ts`: DEATH_KNOCKBACK_MAX = ftToPx(8) [was 60, now 64]
- `projectileCleanupSystem.ts`: CULL_MARGIN = ftToPx(12.5) [still 100]

### Tests updated

10 assertions updated across 5 files to wrap `def.fieldName` with `ftToPx()`:

- `melee-weapons.test.ts`: bladeLength, headRadius, knockback ECS assertions
- `thrown-weapons.test.ts`: maxRange ECS assertion
- `trap-weapons.test.ts`: triggerRadius, explosionRadius ECS assertions
- `beam-weapons.test.ts`: lineDamage.length ECS assertion
- `magic-weapons.test.ts`: aoeOnImpact.radius ECS assertion

## Important Design Decision: WEAPON.\* Constants vs WeaponDef

`WEAPON.*` distance constants in `constants.ts` are NOW IN PIXELS (via `ftToPx(tuning.*)`). They are used by systems that read them directly in pixel space (e.g., enemyAI). **WeaponDef** distance fields use literal feet values (not `WEAPON.*` constants) to avoid double-conversion at the weaponSystem boundary.

## Exception: pickupRange

`stats.ts` `STAT_BASE.pickupRange` and related skill/ability bonus values are kept in pixels. The `statsSystem` is a generic loop that writes values directly to ECS without conversion — changing to feet would require a `DISTANCE_STAT_KEYS` set. Since `pickupRange` doesn't currently affect gameplay (collision uses sprite dimensions), this is deferred. Use `pxToFt()` at UI display time.
