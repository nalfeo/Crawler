### Option A door-aware rebuild — ATTEMPTED, REVERTED — and the partial-path guard (load-bearing lesson)

After the refined-B baseline (static all-doors, 30/36) the creator directed **Option A: exact door-aware reachability parity** — rebuild the navmesh geometry from the shared `buildDoorAwarePassable(world)` predicate whenever the blocked-door set changes, so the navmesh reachable graph would exactly mirror LEGACY's grid reachability at every instant (a true apples-to-apples A/B for Slice 4). I wired it in ~10 LOC by reusing the existing **`navEpoch`** (a canonical-sorted, seed-derived, order-independent blocked-door signature that already invalidates the goal memo) as the rebuild trigger — satisfying the order-independent/seed-derived/amortized guardrails directly — plus a Gate-2 rebuild-determinism test case. Rounds 1–2 gates + a round-4 multi-model review all passed clean.

**Then the Gate-3 sweep collapsed to NAVMESH 3/36 (vs B's 30/36).** Root-caused airtight via a seed-1 sword `NAVDIAG` trace: recast's `computePath` returns **`success=true` with a nearest-reachable PARTIAL path** when start and goal fall in **disconnected navmesh polygon components**. Under Option A, a re-locked door removed ONE tile (`passableTiles` 9551→9550) at rebuild #3, which **SEVERED the recast polygon mesh but NOT the 4-connected grid**. `queryWorldPath` then returned `success=true`, `lastWpToGoalFt=457.4`, a 1–2 waypoint stub. The follower's naive `if (result.success && result.waypoints.length > 0)` accepted the stub, consumed it, emptied `navWaypoints`, and re-queried every poll → the agent **froze ~457ft short of the goal** → timeout.

**THE LOAD-BEARING LESSON:** _recast navmesh reachability is a strict SUBSET of grid reachability at thin/door connectors under the pinned deterministic config (cs/ch 0.25, minRegionArea 8, +Y winding, walkableRadius 0)._ Contour/region simplification pinches thin connectors off the polygon mesh even where the grid stays 4-connected. This makes **Option A (door-aware geometry rebuild) IMPOSSIBLE with recast, not merely buggy** — removing tiles severs the mesh. It also means **door lock/unlock semantics must live at the query-time COST layer (Slice 4), NOT in geometry** (standard navmesh practice): static walkable footprint + dynamic door/threat costs at query time. Encoding dynamic lock-state in geometry is exactly what created the fragility.

The creator **reversed A→B** on this evidence (a falsified premise, not flip-flopping). The shipped design:

1. **Static all-doors Option-B geometry** (`isPassable || isDoor`), built ONCE per floor, **no `navEpoch` rebuild** — one static build, robust (30/36), no severing surface, and the golden `75917f12` **is** this all-doors build (so the Linux re-proof, CI `28938719103`, already validated it directly).
2. **A PERMANENT partial-path guard** in `moveTowardViaNavmesh` (`bt-ai-provider.ts`): after `queryWorldPath`, if the route's **final waypoint lands within `NAV_GOAL_REACHED_FT` (8ft = 2 tiles) of the resolved goal**, accept it (IDENTICAL to the pre-guard accept branch → the 30/36 are unaffected); if it is a **non-reaching PARTIAL stub** (`lastWp` defined but > 8ft), **defer that poll to grid-A\* `moveToward`** (pure locomotion over the door-aware graph, independent `path*` state, NO danger/reward → refined-B intact) instead of consuming the stub; if there is **no route at all** (`lastWp` undefined), the unchanged COLLECT give-up. Report-only fire-instrumentation: an UNCONDITIONAL `navPartialPathFallbacks` counter (sim never reads it → determinism-safe) + an env-gated (`NAVGUARD_STATS=1`) per-fire log. New tuning const `NAV_GOAL_REACHED_FT = 8` in `bt-ai-tuning.ts`.

**Guard result (36-pair sweep, `files/navmesh-sweep-Bguard.json`): NEAR-DORMANT — 8 fires across 1/36 pairs (baseball-bat seed 8 only), 0 outcome / 0 win-loss / 0 time changes vs the pre-guard B baseline.** So the guard is **proven-necessary yet proven-non-destructive**: baseball-bat s8 proves recast severs a thin connector **even in the STATIC all-doors mesh** (the recast⊊grid lesson is general, not an Option-A artifact) — but that seed is a death in LEGACY too, the guard fires, falls back to grid-A\*, and the outcome/timing is unchanged. The A/B stays ~99% pure navmesh. Determinism-safe: the guard's `moveToward` fallback is the same grid-A\* LEGACY runs (Gate-1-proven cross-platform), the `hypot < 8ft` detect is robust (the stub is ~457ft short — no float-epsilon flip), and the golden `75917f12` never exercises the guard (its queries reach). **Ship-autonomously threshold met** (creator's rule: PING only if the guard fires on a majority of seeds OR changes ≥3 outcomes — neither holds).

**Strategic risk for later floors (Slice 4):** on Floor 1 today every locked door is a dead-end, so the all-doors superset never routes through a locked door. A later floor with a **locked-door SHORTCUT** (a locked door on the shortest path, not a dead-end) would let the all-doors mesh route the agent toward a door it cannot pass — the guard would then fire load-bearingly (grid-A\* would also stall at the lock). **This is precisely what Slice-4's query-time door/threat cost layer must handle** (mark locked-door edges high-cost/impassable at query time over the static geometry). Documented, not a Floor-1 blocker.

## Retrospective

### Lessons Learned

- **recast navmesh reachability ⊊ 4-connected grid reachability at thin/door connectors (under the deterministic pinned config), AND `computePath` hides it behind `success=true`.** This is the load-bearing lesson of the slice. Contour/region simplification (cs/ch 0.25, minRegionArea 8) pinches thin connectors off the polygon mesh even where the grid stays connected, so a start/goal pair can land in disconnected navmesh components. When it does, recast returns `success=true` with a **nearest-reachable PARTIAL path** (final waypoint far short of the goal), NOT a failure — a follower that trusts `success` alone will freeze on the stub. TWO consequences: (1) **dynamic door-lock connectivity cannot be tracked via geometry rebuild** — removing a re-locked-door tile severs the mesh (this killed Option A: 3/36). (2) Even a STATIC all-doors mesh has occasional severed thin connectors (baseball-bat s8), so a **partial-path guard is a permanent necessity**: always check the returned route actually reaches the goal (`hypot(lastWp, goal) <= threshold`) and fall back to grid-A\* otherwise. Model door/threat semantics at the query-time COST layer, never in geometry.
- **A determinism proof on degenerate output is worthless — validate correctness first.** Slice 1 proved byte-identical waypoints across platforms and called it GO, but never checked the paths actually LEFT the spawn room. They didn't. The lesson: a "same bytes everywhere" proof must be paired with a "the bytes describe a CORRECT result" check. The strengthened Gate-2 test now asserts goal-reachability precisely so this can't recur silently.
- **Door tiles are non-passable in the raw generated map.** Anything building a connectivity graph straight from `tileMap.isPassable` will get one sealed island per room. Use `isPassable || isDoor`.
- **recast cell size interacts with corridor width.** cs=0.5 gives 2 cells per tile — a 1-tile corridor gets pinched off by contour/region simplification. cs=0.25 (4 cells/tile) survives. `minRegionArea` must be ≥8 (1 crashes `buildPolyMeshDetail`).
- **`node ./node_modules/vitest/vitest.mjs run --project headless` is the reliable local vitest invocation on this Windows worktree** — the `.bin/vitest` shim is missing so `npx`/`npm exec` fail; `npm run <script>` works (npm prepends `.bin` to PATH). Headless project = 180s testTimeout; unit = 30s (contention-flake source). Set `$env:CI='1'`.
- **Run heavy checks ALONE.** A full headless suite with 5 concurrent review agents took ~1375s (~4.5× normal) and produced spurious wall-clock timeouts. Isolate the machine for headless/sweep runs.
- **Stale-base diff quirk:** local `origin/main` advanced past this branch's base, so plain `git diff origin/main` is polluted. Use `git diff 94bf9f62..HEAD` (or `git diff 94bf9f62` for working tree) for the clean Slice-3 diff.

Next agent: if recast paths are uniformly 2 points, suspect connectivity/cell-size before anything else.
