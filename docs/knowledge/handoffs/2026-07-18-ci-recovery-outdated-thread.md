## Problem

PR #1542 had 3 unresolved review threads. The CI recovery automation exhausted its 2-attempt retry budget without making progress. Three consecutive recovery tasks (07:14, 08:21, 09:17) were dispatched, and a code fix (`e4c1fc5`) was pushed, but none of the agents ever posted `✅ Addressed` replies to the threads.

## Root Cause

The task body generated by `reconcile.mjs` did **not** annotate the `isOutdated` status of review thread blockers. After `e4c1fc5` was pushed:

- Threads `x4` and `yE` became `isOutdated: true` (their source lines were modified/removed)
- Thread `x_` was tracked by GitHub to a different line that no longer contained the reviewed code

Recovery agents receiving tasks for these threads could not distinguish:
1. Threads that are **outdated** (deterministic non-applicability — should immediately resolve)
2. Threads that are **still current** (need code fix + different-model validation before resolving)

Without the `isOutdated` flag, agents over-validated or got confused by stale line positions and failed to post `✅ Addressed` markers.

**Secondary issue (also fixed):** `normalizeBlockers` in `state.mjs` did not include `isOutdated` in the normalized shape, so for file-level review threads that have no `line` field, transitioning `isOutdated: false → true` did NOT change the blocker fingerprint. This prevented the automation from detecting "progress" (fingerprint change = retry budget reset) in that edge case.

## Fix

Two surgical changes:

### 1. `reconcile.mjs` — blocker push adds `isOutdated`

```diff
   kind: 'review-thread',
   id: reviewThreadBlockerId(thread),
   threadId: thread.id,
   path: thread.path || undefined,
   line: thread.line || undefined,
+  isOutdated: thread.isOutdated === true,
   summary: ...
```

### 2. `reconcile.mjs` — task body annotates outdated threads

```diff
- `${index + 1}. **${blocker.kind}** \`${blocker.id}\`${blocker.path ? ...}`
+ `${index + 1}. **${blocker.kind}** \`${blocker.id}\`${blocker.path ? ...}${blocker.isOutdated ? ' **(outdated — deterministic non-applicability candidate)**' : ''}`
```

### 3. `state.mjs` — `normalizeBlockers` includes `isOutdated`

```diff
   ...(Number.isFinite(blocker.line) ? { line: blocker.line } : {}),
+  ...(blocker.isOutdated === true ? { isOutdated: true } : {}),
```

## Regression Test

Added to `state.test.mjs`: `normalizeBlockers preserves isOutdated flag and it is included in the fingerprint` — verifies that:
1. `isOutdated: true` survives normalisation
2. `isOutdated` absent/false does NOT set the field
3. Fingerprints differ between outdated and fresh blockers (retry budget resets on transition)
