# CI Recovery Loop: blockerFingerprint excludes self-generated copilot failure

**Date:** 2026-07-29  
**Session slug:** fix-ci-recovery-loop  
**Apple estimate:** 1🍎 (tooling-only)  
**Closes:** #2268 (CI recovery loop incident for PR #1939)

## Systems touched

ci-recovery

## Problem

PR #1939 ("pin all direct dependencies to exact versions; add check-exact-deps CI guard")
triggered a CI recovery loop incident (#2268). The automated CI recovery pipeline made no
progress after 2 attempts.

**Root cause #1 — deprecated model (external, already fixed)**  
The model `claude-sonnet-4.5` was deprecated on 2026-05-06. Every time the CI recovery
assigned @copilot to fix PR #1939's review threads, the dynamic `copilot-swe-agent/copilot`
workflow resolved `model=auto → claude-sonnet-4.5` and failed immediately at `session.create`
with `Model "claude-sonnet-4.5" is not available`. This created a check-run named `copilot`
that concluded `failure` on the PR's head SHA.

**Root cause #2 — deterministic defect in `blockerFingerprint` (this PR)**  
When the self-generated `copilot` check-run appeared as a *new* `ci-failure copilot` blocker on
the next reconcile sweep, it changed the blocker fingerprint from F₁ (review threads only) to
F₂ (review threads + copilot failure). `automationStallAction` reads a changed fingerprint as
`'progressed'` — genuine new progress on the PR. This reset the attempt counter to 1 and gave
the loop more retries than the stale-automation ceiling (`attempt >= 2`) was meant to allow:

```
Without fix:
  Dispatch (attempt=1, F₁) → @copilot fails → F₂ appears → 'progressed' → attempt reset
  Dispatch (attempt=1, F₂) → @copilot fails → same F₂ → 'stale' → attempt=2 → 'release'
  → incident filed (3 total cycles)

With fix:
  Dispatch (attempt=1, F₁) → @copilot fails → copilot excluded from fingerprint → F₁ unchanged
  → 'stale' → attempt=2
  Dispatch (attempt=2, F₁) → @copilot fails → 'stale' → attempt>=2 → 'release'
  → incident filed (2 total cycles, one fewer dispatch to a broken model)
```

Note: PR #1939's review thread bugs (`isExempt` version-binding, `fileURLToPath` path handling)
had **already landed on `main`** as part of the merge-train squash of PR #2262 at commit
`e7cd59c` — before this session started. PR #1939 now has a merge conflict and will need to be
closed or rebased.

## Fix

**File:** `.github/scripts/ci-recovery/state.mjs` — `blockerFingerprint`

Added a `.filter((b) => !(b.kind === 'ci-failure' && b.id === 'copilot'))` step before the
existing `.map(({ line, url, ...rest }) => rest)` projection. The filter excludes the
self-generated copilot check-run from the fingerprint hash. The blocker is still **persisted
to state** for display/evidence — it is only invisible to the fingerprint comparison.

This mirrors the prior `url`-exclusion fix (PR #1809): display-only metadata that is always
generated by the CI recovery itself must not participate in the fingerprint, or it will be
misread as independent external progress.

## Tests added

- **`state.test.mjs`**: Unit test verifying that `blockerFingerprint([ci-failure-copilot, RT])
  === blockerFingerprint([RT])` and that non-copilot ci-failures are still fingerprinted.
- **`reconcile.test.mjs`**: Integration test (end-to-end through reconcile.mjs subprocess)
  for the exact PR #1939 scenario: automation-dispatched state with review-thread blockers,
  attempt=1, stale; current check runs include a fresh `copilot` failure; asserts
  trigger=stale-automation-retry and attempt=2 (NOT blocker-progressed with attempt reset).

## Decisions

- Excluded from **fingerprint only** (not from blockers list): the copilot failure is still
  written to state for transparency and included in the task body sent to the next @copilot
  dispatch. Only the hash changes.
- Used `b.id === 'copilot'` (exact match, not `.includes`): the check-run is always named
  exactly `copilot` (GitHub's fixed name for the dynamic copilot-swe-agent workflow). The
  existing lower-case conversion in the blocker-detection loop ensures this is stable.

## What's NOT in this PR

- PR #1939's own branch is still broken (merge conflict + the two code bugs in the old
  `check-exact-deps.mjs`). The fixes are already on `main`. PR #1939 should be closed as
  superseded by `e7cd59c`.
- The deprecated model issue is out of scope for the CI recovery tooling: the underlying
  cause is a GitHub/Copilot configuration that resolves `auto` → `claude-sonnet-4.5`. CI
  recovery can't control model resolution. Filing the loop incident (#2268) and reducing the
  wasted dispatch count (via this fix) is the correct response.
