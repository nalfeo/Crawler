# Handoff: Fix GitHub Pages /dev/ 404

**Date**: 2026-06-21  
**Session**: Fix GH Pages 404 at nalfeo.github.io/Crawler/dev/

## Problem

`https://nalfeo.github.io/Crawler/dev/` was returning 404 despite the `gh-pages` branch containing `dev/index.html`.

## Root Cause

GitHub Pages for this repo is configured to use **GitHub Actions** as the deployment source (not "Deploy from a branch"). The deploy workflow was pushing content to the `gh-pages` branch, but Pages only serves content deployed via `actions/deploy-pages` when GitHub Actions source is selected.

Evidence: the "Ensure GitHub Pages source is set to gh-pages branch" step in `deploy.yml` was failing with `403 Resource not accessible by integration` — this error specifically occurs when Pages is configured for Actions source and you try to switch it to branch source via the API.

## Fix

Updated `deploy.yml` and `pr-preview.yml` to use the official GitHub Actions Pages deployment mechanism:

1. **`deploy.yml`**:
   - Added `id-token: write` permission (required by `actions/deploy-pages`)
   - Added `environment: name: github-pages` to the job
   - Renamed "Deploy to gh-pages branch" → "Sync gh-pages branch" (still keeps the branch as a staging area for PR preview preservation)
   - Added "Merge PR previews into site artifact" step (copies `pr-*/` dirs from gh-pages into the `site/` artifact)
   - Added `actions/upload-pages-artifact@v3` + `actions/deploy-pages@v4` steps
   - Removed the failing "Ensure GitHub Pages source is set to gh-pages branch" step

2. **`pr-preview.yml`**:
   - Added `id-token: write` and `pages: write` permissions
   - Added `environment: name: github-pages` to the job
   - After pushing to gh-pages branch, uploads the full gh-pages content as a Pages artifact and deploys it via `actions/deploy-pages@v4`
   - This makes PR preview URLs (nalfeo.github.io/Crawler/pr-NNN/) live immediately

## Architecture After Fix

- **gh-pages branch**: Used as a staging area. Contains all site content (dev/, beta/, pr-NNN/, index.html). Written by both deploy.yml and pr-preview.yml.
- **GitHub Pages (live site)**: Served via GitHub Actions Pages deployment. Updated by both deploy.yml (full deploy) and pr-preview.yml (includes PR preview + current site content).
- **pr-preview-cleanup.yml**: Still only writes to the gh-pages branch. The removed pr-NNN/ directory will be absent from the next Pages deployment.

## Prerequisites

GitHub Pages must be configured in repo Settings → Pages → **Source: GitHub Actions**. If it's not enabled at all, a repo admin must enable it there first.
