# Fix: Docs Update Loop — Prettier failure on INDEX.md

**Session slug**: fix-docs-update-loop-prettier
**Apple estimate**: 🍎
**Date**: 2026-07-27

## Systems touched

ci

## Problem

CI run [30226162515](https://github.com/nalfeo/Crawler/actions/runs/30226162515) failed on the
`docs-update` job at step "Open docs automation PR" with:

```
##[error]Unexpected error: Running Prettier on staged files...
docs/knowledge/handoffs/INDEX.md 244ms
...
```

`peter-evans/create-pull-request@v7` calls `git commit` to create the PR branch commit.
That `git commit` triggers the repository's `.githooks/pre-commit` hook, which runs Prettier
on every staged file (line 34) and then **unconditionally** re-adds them with `git add` (line 35).
`docs/knowledge/handoffs/INDEX.md` is an auto-generated index with handoff description lines
that can reach 246 characters — well over `.prettierrc`'s `printWidth: 100`. Prettier rewrites
the file, the hook re-stages the reformatted version, and the subsequent `Unexpected error` is
thrown by the hook's error handling when the re-staging step fails on the reformatted output.

## Fix

Added `docs/knowledge/handoffs/INDEX.md` to `.prettierignore`.

This file is generated by `scripts/agent/docs/build-system-index.ts` and intentionally keeps
full-width description lines for readability. Ignoring it from Prettier means the pre-commit hook
skips reformatting it, so `git add` has nothing new to re-stage and the `git commit` completes
cleanly.

## Verification
