## Unresolved / known gaps

1. **Cache bypasses per-variant budget gate.** `generate-one.ts:305` reads
   `if (... wouldExceed() && !options.judgeCache)` — when a cache is
   provided the per-variant gate is skipped. Side effect: a brief that
   starts under-budget runs ALL its variants even if mid-brief spending
   blows past the cap. The BATCH layer still stops the NEXT brief.
   Documented in `sprite-style.md` under "Known interaction". Fix
   would be a follow-up PR that tightens the per-variant gate to honor
   the budget even with a cache present.
2. **`JudgeBudget.stateFile` path is fragile under concurrent batches.**
   Two simultaneous batches with the same state file would race. Not a
   regression — same shape as single-brief — but worth knowing.
3. **`projectDryRunCost` is pessimistic and hardcoded to gpt-4o rates.**
   Good enough for "is this in the right ballpark" but not for
   accounting. Future improvement: read brief `maxVariants` and the
   judge's actual deployment, rather than assuming 4 variants + gpt-4o.
